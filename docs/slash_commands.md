# Слэш-команды TUI

Команды вводятся в строке ввода TUI (или обрабатываются в `arch run` через
сессию). Реализация — `src/agent/slash.rs` (`execute`), каталог с
описаниями — `catalog()` (источник `/help` и автодополнения по Tab).

Семантика исходов (`SlashOutcome`): команда обработана — текст показывается
блоком в чате; ввод не начинается с `/` — уходит модели; неизвестная
команда — диагностика; `/quit` — выход. Ошибки подкоманд (файл не найден,
модель недоступна) — красным блоком ошибки; проблемы использования (нет
аргументов) — подсказкой по синтаксису.

## Сессия и модель

### `/help`
Справка: таблица всех команд из каталога.

### `/model [name]`
Без аргумента — **пикер моделей**: модальная панель со списком `[models]`
(описание — id модели и метка `ризонинг: /think`, ★ и курсор — текущая;
`↑/↓`, `Enter`, цифры — выбор, `Esc` — отмена). С аргументом — переключение
на лету (`AgentSession::set_provider`), минуя пикер.

```
/model             → ◈ выбор модели (модалка)
/model kimi        → модель переключена: kimi (kimi-k3)
```

### `/think [on|off|auto]`
Переключатель ризонинг-режима активной модели. `on`/`off` сливают в тело
запроса карту `thinking_on`/`thinking_off` из конфига модели (DeepSeek V4 и
GLM-4.x: `thinking.type`; Kimi K3: `reasoning_effort`). `auto` — дефолт
провайдера, параметры не шлются. Без аргумента — статус и фактические карты.
Если карт в конфиге нет — вежливый отказ с подсказкой. Индикатор в
статус-баре: `🧠` / `🧠off` у бейджа модели.

```
/think on          → ризонинг: on (deepseek); в тело запроса сливается {"thinking":{"type":"enabled"}}
```

### `/clear`
Очищает историю сообщений сессии (с записью события `clear` в журнал).

### `/new`
Новая сессия на месте текущей: история, детекторы петель и панели TUI
очищены, журнал **ротирован** — в старый пишется `session_end`, диалог
дальше идёт в новый файл (старые журналы доступны через `/sessions` и
`/resume`). Модель и переключатель `/think` сохраняются. Журналы сессий
никогда не перемешиваются: суффикс `-n` разводит коллизию одной секунды.

### `/compact`
Принудительная компактификация контекста вне автоматических порогов:
L1-маскирование старых tool-результатов + L3-саммари истории до последнего
user-сообщения (LLM-сводка целей/решений/шагов). Отчёт — статистика
«~было → ~стало ток., свёрнуто/усечено»; в журнал — событие `compact_manual`.
Автоматика: пороги 70% (L1) / 95% (L3) от `min(agent.context_budget_tokens,
context_limit активной модели)` — см. `docs/models.md`.

### `/quit`
Выход из TUI (также `q`, `Ctrl-C`; `Esc` — в простое, а во время хода
`Esc`/`Alt+Enter` прерывают ход и сразу запускают срочное сообщение из
очереди — см. «Отмена хода» в `docs/architecture.md`).

### `/skills [query]`
Без аргумента — список всех скиллов библиотеки плагинов; с запросом — поиск (name ×12, description ×6, keywords ×4, тело ×1) со сниппетами. Подробности: `docs/plugins_and_skills.md`.

### `/skill <name>`
Загружает полный текст скилла и включает его в контекст текущей сессии (`inject_context`) — модель дальше следует методике скилла.

### `/plugins [name]`
Список плагинов (скиллы + MCP + субагенты + хуки) или подробности одного: манифест, скиллы, MCP-серверы.

### `/agents`
Субагенты: спецификации из плагинов (`agents/*.md`: имя, плагин, whitelist инструментов) и статусы фоновых задач (running/done/failed, превью отчётов). Запуск — через агента фразой «запусти <имя> на <задачу>» (инструмент `subagent_run`).

### `/worktree`
Список изолированных git worktree фабрики для текущего репозитория (ветки `arch/*`: имя, путь, на сколько коммитов впереди, чистый/грязный). Создание — инструментом `worktree_new` (через агента) или `arch worktree new <name>`; review — `arch worktree diff`, accept/drop — человеком.

### `/distill <name> [plugin]`
Дистиллирует транскрипт текущей сессии в скилл библиотеки: хвост контекста (≤24k символов) уходит в модель с промптом `skill_distiller`, результат — `plugins/<plugin>/skills/<name>/SKILL.md` (по умолчанию plugin = `arch-distilled`, managed-зона с разрешённой перезаписью). Статью дистиллирует инструмент `skill_distill` (через чат).

### `/agentsmd <repo>`
Генерирует/обновляет AGENTS.md репозитория из архитектурных артефактов (spine, CONSTRAINTS, манифесты) и прогоняет линтер. Рукописная зона вне маркеров `ARCH:GENERATED`/`ARCH:END` сохраняется. Подробности: `docs/agents_md.md`.

### `/sessions`
Журналы прошлых сессий из `paths.sessions_dir`: файл, дата, число сообщений, первая реплика.

### `/resume [file|last]`
**Без аргумента — пикер сессий**: модальная панель с журналами из
`paths.sessions_dir` (новые первыми, текущая скрыта; описание — дата, число
сообщений, превью первой реплики); `↑/↓`/`j/k`, `Enter` — выбор, цифры —
быстрый выбор, `Esc` — отмена. С аргументом восстанавливает историю из
журнала напрямую (`last` — новейшая, кроме текущей). Переносятся реплики
user/assistant; вызовы инструментов остаются в журнале.

### `/save <file>`
Сохраняет транскрипт сессии в markdown (`# Транскрипт сессии`, секции
`## <роль>`, вызовы инструментов списком). Путь резолвится от cwd.

```
/save transcripts/payment-review.md
```

### `/load <file>`
Включает содержимое файла (не более 16 384 символов, с пометкой об
усечении) в контекст как user-сообщение — без обращения к модели.

```
/load docs/specs/payment.md   → включено: 1620 символов
```

### `/memory [add <текст>]`
Глобальная md-память харнесса (файл `paths.memory_file`, по умолчанию
`~/.arch-harness/MEMORY.md`): её содержимое дописывается в системный промпт
каждой сессии (TUI и `arch run`), агент поддерживает её сам fs-инструментами.
Без аргумента — путь к файлу и содержимое; `add` — дописать заметку в конец
(файл создаётся при отсутствии). Из shell: `arch memory` / `arch memory add`.

```
/memory add пользователь предпочитает саги с оркестрацией
```

## Инструменты и промпты

### `/tools`
Список инструментов текущей сессии с первой строкой описания (ядро +
доменные + MCP, если `connect_on_start = true`). Полный справочник с
параметрами, примерами и лимитами — `docs/tools.md`.

### `/prompts [name]`
Без аргумента — библиотека шаблонов (`assets/prompts/*.md`: имя файла =
имя шаблона, первая строка `# ...` — описание). С аргументом — тело
шаблона целиком.

```
/prompts
/prompts adr
```

## Архитектурные артефакты

### `/mermaid <file|код>`
Рендер mermaid в Unicode/ASCII. Аргумент, начинающийся с `graph`,
`flowchart` или `sequenceDiagram`, рендерится как inline-код; иначе —
путь к файлу (от cwd). Результат попадает также на вкладку «Mermaid».

```
/mermaid examples/mermaid/flow.mmd
/mermaid flowchart LR\nA[Каналы] --> B[API Gateway]
```

### `/adr new <title>`
Новый ADR по шаблону AI-DLC в `docs/adr` рабочего каталога
(`control::adr_new`): файл `ADR-NNN-kebab-title.md` с очередным номером.

```
/adr new Выбор брокера событий для платёжного контура
```

### `/spine lint <file>`
Линтер ARCHITECTURE-SPINE.md: дубли AD-id, пустые/отсутствующие поля
Binds/Prevents/Rule, заглушки, непиннутые версии, битые ссылки на AD
(правила — `docs/control.md`).

```
/spine lint docs/ARCHITECTURE-SPINE.md
```

### `/score [триггер=true ...]`
Architecture Significance Score → маршрут Fast/Standard/Critical.
Без аргументов — справка по 15 триггерам. Значения истины:
`true`, `1`, `yes`, `да`.

```
/score new_component=true trust_zone_change=true
```

## Оценка и бенчмарки

### `/rubric list`
Список якорных рубрик каталога `assets/rubrics` (имя, число критериев,
описание).

### `/rubric run <name> <file>`
Оценка файла LLM-судьёй моделью по умолчанию; markdown-отчёт выводится
в чат и на вкладку «Рубрика».

```
/rubric run adr_quality docs/adr/ADR-001-kafka.md
/rubric run solution_architecture docs/solution.md
```

### `/bench list` / `/bench run <name>`
Список бенчмарков / прогон сценария на модели по умолчанию с оценкой
рубрикой; вердикт PASS/FAIL и взвешенный балл против порога, отчёты — в
`reports/`.

```
/bench run payment_integration
```

## Знания и веб

### `/kb <query>`
Поиск по локальной базе знаний (`knowledge.dirs`): до 10 хитов со
сниппетами (маркер `>>>` на строке совпадения) и скором.

```
/kb идемпотентность платежей
```

### `/web <query>`
Поиск DuckDuckGo, ограниченный кураторскими сайтами архитектора
(`site:domain` на каждый сайт из `web.arch_sites`).

```
/web outbox pattern kafka
```

### `/fetch <url>`
Загрузка страницы текстом (html→text, усечение до `web.max_fetch_chars`).

```
/fetch https://microservices.io/patterns/data/transactional-outbox.html
```

### `/sites`
Кураторский список сайтов архитектора (имя, домен, описание, базовый URL).

## Харнессы и контроль

### `/handoff <harness> <repo> [task...]`
Генерация handoff-пакета `.arch-handoff/` в репозитории (`docs/harness_integrations.md`).
Без `task` — дефолтная формулировка «См. TASK.md: реализуй согласно
архитектуре».

```
/handoff claude-code ~/work/payment-svc Реализуй платёжный оркестратор по ADR-001
```

### `/control <repo>`
Fitness-контроль репозитория по `<repo>/.arch-handoff/CONSTRAINTS.yaml`:
сводка и находки `[severity] file:line rule — message`, вердикт PASS/FAIL.

```
/control ~/work/payment-svc
```

### `/mcp list`
MCP-серверы из `mcp.json` и их инструменты. Подключение — по требованию
(в ленивом режиме старт TUI серверы не ждёт); сбой сервера — не фатален,
текст ошибки показывается блоком. Подробности — `docs/mcp.md`.

### `/doctor`
Диагностика окружения (10 проверок с ✓/⚠/✗): default_model, API-ключи
(значения не выводятся), каталог сессий на запись, счёт плагинов/скиллов,
база знаний, кодовые харнессы в PATH, MCP и бинари серверов, крон,
кураторские сайты, git. То же из shell: `arch doctor` (exit code 1 при
хотя бы одном ✗ — пригодно для CI/крона).

### `/export <word|excel> [путь]`
Экспорт текущего экрана диалога в `.docx`/`.xlsx` (валида́нные минимальные
OOXML-пакеты; mermaid-арт в Word идёт моноширинным Courier New). Без пути —
`arch-screen-<штамп>.<ext>` в рабочем каталоге. Из shell без TUI:
`arch export <word|excel> <session.jsonl> <out>` — выгрузка прошлой сессии.
